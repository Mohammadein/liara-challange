# دستیار مستندات لیارا

دستیار مبتنی بر LLM برای مستندات لیارا — چالش هکاتون Vibe Coding.

پاسخ‌ها از روی مستندات رسمی لیارا ساخته می‌شوند و هر پاسخ **لینک مستقیم به بخش
مربوطه** در مستندات دارد، نه فقط لینک صفحه.

---

## قابلیت‌های Agentic

**پیشنهاد قدم بعدی.** زیر هر پاسخ دو تا سه چیپ قابل کلیک می‌آید: کاری که کاربر
معمولاً بعدش لازم دارد. چیپ‌ها از پاسخ و صفحات واقعیِ بازیابی‌شده ساخته می‌شوند،
با یک تماس **مدل کوچک** و سقف توکن پایین. اگر آن تماس شکست بخورد، پیشنهادها از
عنوان صفحات بازیابی‌شده ساخته می‌شوند — پس این قابلیت هیچ‌وقت پاسخ را خراب
نمی‌کند. (`app/suggest.py`)

**فرآیندهای چندمرحله‌ای.** بعضی کارها یک سؤال نیستند، یک مسیرند. پنج فرآیند
تعریف شده: استقرار برنامه، راه‌اندازی دیتابیس و اتصال آن، دامنه اختصاصی و
HTTPS، عیب‌یابی استقرار ناموفق، و فضای ذخیره‌سازی. (`app/flows.py`)

- **اسکلت قطعی، محتوای بازیابی‌شده.** ترتیب، عنوان و صفحه‌ی مرجع هر قدم در کد
  ثابت است؛ مدل حق ساختن یا جابه‌جا کردن قدم را ندارد. متن هر قدم از مستندات
  همان قدم نوشته می‌شود، پس نه قدمی جا می‌افتد و نه لینکی توهم می‌شود.
- **قدم‌ها با پروفایل پروژه پر می‌شوند:** کاربر جنگویی صفحه‌ی Django می‌گیرد و
  کاربر PostgreSQL صفحه‌ی PostgreSQL.
- **وضعیت ماندگار است** (ستون `flow_json` در `sessions`)، پس کاربر می‌تواند
  فردا از همان قدم ادامه بدهد.
- **«قدم بعد» هیچ تماس اضافه‌ای با مدل ندارد** — ناوبری قاعده‌محور است.
- شروع فرآیند فقط با درخواست صریح («قدم به قدم»، «از صفر»، «راهنمای کامل») به
  علاوه‌ی موضوع اتفاق می‌افتد؛ یک سؤال ساده کاربر را وارد فرآیند نمی‌کند.

هر دو قابلیت در UI **دیده** می‌شوند: stepper بالای پاسخ و چیپ‌های زیر آن.
شکل دقیق رویدادها در [CONTRACTS.md](CONTRACTS.md).

## اجرا روی لپ‌تاپ

```bash
# ۱. محیط مجازی
python -m venv .venv
.venv\Scripts\activate        # ویندوز
# source .venv/bin/activate   # لینوکس / مک

# ۲. وابستگی‌ها
pip install -r requirements.txt

# ۳. تنظیمات
copy .env.example .env        # ویندوز
# cp .env.example .env

# ۴. اجرا
uvicorn app.main:app --reload
```

باز کنید: <http://127.0.0.1:8000>

با `USE_MOCK=true` (پیش‌فرض) بدون کلید API و بدون ایندکس کار می‌کند — پاسخ‌های
ساختگی می‌دهد که دقیقاً قرارداد واقعی را رعایت می‌کنند.

تاریخچه‌ی گفتگوها در SQLite نگه‌داری می‌شود. هر مرورگر یک شناسه‌ی ناشناس
دارد، بنابراین کاربر می‌تواند گفتگوهای قبلی را از سایدبار باز کند و با همان
context ادامه دهد. مسیر پیش‌فرض دیتابیس `data/sessions.db` است.

## ساخت ایندکس مستندات

مخزن مستندات جدا کلون می‌شود (در `.gitignore` هست):

```bash
git clone --depth 1 https://github.com/liara-cloud/docs.git docs
python -m ingest.run_all
```

خروجی در `data/`: `chunks.json`، `vectors.npy`، `bm25.pkl`

تست نگاشت مسیر به URL (بدون نیاز به کلید API):

```bash
python -m ingest.config
```

## ساختار

```
ingest/     خط لوله آماده‌سازی داده — فقط روی لپ‌تاپ اجرا می‌شود
  config.py     مسیرها، نگاشت مسیر→URL، برچسب‌ها
  schema.py     قرارداد داده (قفل)
data/       خروجی ingest — commit می‌شود تا داخل ایمیج برود
app/        اپلیکیشن FastAPI
  contracts.py  قرارداد API (قفل)
  flows.py      کاتالوگ فرآیندهای چندمرحله‌ای — ترتیب و لینک قدم‌ها، قطعی
  suggest.py    ساخت چیپ‌های «قدم بعدی»
  mock.py       پاسخ‌های ساختگی برای کار موازی فرانت
  settings.py   تنظیمات از env
  session.py    ذخیره پایدار گفتگوها، پروفایل، و وضعیت فرآیند در SQLite
  api_sessions.py  فهرست، بازیابی، تغییر نام و حذف گفتگوها
  main.py       روت‌ها
static/     رابط کاربری — بدون CDN، همه‌چیز محلی
eval/       مجموعه سؤال طلایی برای سنجش کیفیت بازیابی
```

قراردادهای بین بخش‌ها: [CONTRACTS.md](CONTRACTS.md)
نقشه راه و تقسیم کار: [PLAN.md](PLAN.md)

## استقرار روی لیارا

```bash
npm i -g @liara/cli
liara login
liara deploy
```

`liara.json` روی `platform: docker` تنظیم شده تا کنترل کامل روی ایمیج داشته باشیم.

متغیرهای محیطی روی کنسول لیارا تنظیم می‌شوند (نه در ریپو):

| متغیر | توضیح |
|---|---|
| `LIARA_AI_BASE_URL` | آدرس سرویس هوش مصنوعی از کنسول لیارا |
| `LIARA_AI_API_KEY` | کلید API |
| `USE_MOCK` | روی `false` |
| `SESSION_DB_PATH` | مسیر SQLite روی Liara Disk، مثلاً `/data/sessions.db` |

برای اینکه تاریخچه با استقرار مجدد پاک نشود، در لیارا یک Disk متصل کنید و
`SESSION_DB_PATH` را روی مسیر همان Disk قرار دهید.

## تصمیم‌های معماری

**ذخیره وکتور در حافظه، نه دیتابیس.** حدود ۹۰۰۰ تکه × ۱۰۲۴ بعد ≈ ۳۷ مگابایت.
جستجو یک ضرب ماتریسی numpy است که زیر یک میلی‌ثانیه طول می‌کشد. Postgres یا
Qdrant برای این حجم، هزینه و یک نقطه شکست اضافه می‌آورد بدون هیچ سود عملی.

**بازیابی هیبریدی.** جستجوی معنایی روی اسم سرویس‌های خاص («لیارا دیسک»،
«Object Storage») ضعیف است، پس BM25 کلیدواژه‌ای هم اجرا می‌شود و نتایج با RRF
ترکیب می‌شوند. متن فارسی قبلش نرمال می‌شود (`ي→ی`، `ك→ک`، نیم‌فاصله).

**بدون CDN در فرانت.** هر کتابخانه‌ای لازم شود داخل `static/` کپی می‌شود.
وابستگی به CDN یعنی ریسک روی زیرساخت و روی مرورگر داور.

**ارجاع با anchor.** کامپوننت `<Section id="...">` در مستندات لیارا دقیقاً
anchor صفحه است، پس هر منبع به همان بخش لینک می‌شود نه به بالای صفحه.
